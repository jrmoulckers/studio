# JRM Studio

The **design + tooling kernel** for JRM Studio (npm scope `@jrm`). This pnpm + Turbo
monorepo publishes the shared packages every product repo consumes — Next.js
(`jrm-recipes`), a Svelte/Vite PWA (`score-king`), a Gradle+Turbo app (`finance`), and more
to come — so they all share **one design-token source of truth** and **one set of config
presets**.

Per-product themes = swap the semantic palette while keeping the system (names, components,
scales, and build outputs stay identical).

## What's inside

| Package | Role |
| ------- | ---- |
| [`@jrm/tokens`](packages/tokens) | DTCG design tokens (seeded from score-king) → **CSS custom properties**, a **Tailwind preset**, and **typed JS/TS** objects |
| [`@jrm/tailwind-preset`](packages/tailwind-preset) | Ready-to-use Tailwind preset that consumes `@jrm/tokens` |
| [`@jrm/eslint-config`](packages/eslint-config) | Shared flat ESLint config (`base` + `react`) |
| [`@jrm/tsconfig`](packages/tsconfig) | Base TS config + `react` / `svelte` / `node` variants |
| [`@jrm/prettier-config`](packages/prettier-config) | Shared Prettier config (+ Tailwind class sorting) |

Everything is `private` + `0.0.0` — local build/verify only, no publishing yet.

## Workspace commands

```bash
pnpm install          # install all workspace deps
pnpm build            # turbo run build (ordered: tokens → tailwind-preset)
pnpm -r build         # recursive build (same outputs)
pnpm typecheck        # tsc --noEmit across the repo
pnpm lint             # eslint .
pnpm format           # prettier --write .
```

`@jrm/tokens` compiles its DTCG sources with Style Dictionary into `build/` (git-ignored,
regenerated by `pnpm build`):

```
packages/tokens/build/
├── css/default/{tokens.css, tokens-dark.css, tokens-high-contrast.css, index.css}
├── tailwind/default.cjs
└── js/{index.js, index.d.ts, default/tokens.<mode>.{js,d.ts}}
```

## Theming & color modes

The CSS output defines three layers on top of framework-agnostic CSS variables:

- **`:root`** — the `light` (default) palette + every primitive, semantic, and component var.
- **`[data-theme="dark"]`** — the canonical dark palette (the score-king app boots in dark).
- **`[data-theme="high-contrast"]`** — a max-contrast, light-based mode.

Component vars in `:root` reference **semantic names** (`var(--color-primary)`, …), and each
theme block only restates those ~16 semantic colors — so a runtime mode swap re-flows every
component and utility with **no rebuild**. A `prefers-reduced-motion` block collapses motion
durations to `0ms` automatically.

```html
<html>                            <!-- light (default) -->
<html data-theme="dark">          <!-- dark -->
<html data-theme="high-contrast"> <!-- high contrast -->
```

## Consuming in **Next.js** (e.g. `jrm-recipes`)

**1. Import the CSS variables** once in your global stylesheet:

```css
/* app/globals.css */
@import "@jrm/tokens/css";   /* :root + [data-theme] + reduced-motion */
@tailwind base;
@tailwind components;
@tailwind utilities;
```

**2. Apply the Tailwind preset:**

```ts
// tailwind.config.ts
import type { Config } from "tailwindcss";

export default {
  presets: [require("@jrm/tailwind-preset")],
  content: ["./app/**/*.{ts,tsx,mdx}", "./components/**/*.{ts,tsx}"],
} satisfies Config;
```

**3. Set the mode** on `<html>` (persist the user's choice however you like):

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="dark">
      <body>{children}</body>
    </html>
  );
}
```

**4. Use the typed tokens** in TS where you need raw values (charts, canvas, inline styles):

```ts
import { tokens, tokensDark } from "@jrm/tokens";

const brand = tokens.color.primary;       // "#7c5cff"
const darkBg = tokensDark.color.bg;        // "#0f1020"
```

**5. Extend the shared configs:**

```jsonc
// tsconfig.json
{ "extends": "@jrm/tsconfig/react.json" }
```

```js
// eslint.config.js  (flat)
import { base } from "@jrm/eslint-config";
import react from "@jrm/eslint-config/react";
export default [...base, ...react];
```

```jsonc
// package.json
{ "prettier": "@jrm/prettier-config" }
```

## Consuming in **Svelte / Vite PWA** (e.g. `score-king`)

**1. Import the CSS variables** in your app entry CSS — they're plain custom properties, so
they work in Svelte with zero framework glue:

```css
/* src/app.css */
@import "@jrm/tokens/css";
```

```svelte
<!-- Component styles reference the same semantic vars -->
<div class="card">…</div>

<style>
  .card {
    background: var(--color-surface);
    color: var(--color-text);
    border-radius: var(--radius-md);
    box-shadow: var(--shadow-lift);
    transition: border-color var(--motion-state-duration) var(--motion-state-easing);
  }
</style>
```

**2. (Optional) Tailwind** — if the PWA uses Tailwind, the same preset applies:

```js
// tailwind.config.js
module.exports = {
  presets: [require("@jrm/tailwind-preset")],
  content: ["./index.html", "./src/**/*.{svelte,ts,js}"],
};
```

**3. Set the mode** on the document element:

```ts
document.documentElement.dataset.theme = "dark"; // or "high-contrast", or remove for light
```

**4. Typed tokens** work in Svelte `<script>` too:

```ts
import { themes } from "@jrm/tokens";
const playerColors = Object.values(themes.dark.color.player); // 12-color avatar palette
```

**5. Shared configs:** `"extends": "@jrm/tsconfig/svelte.json"`, plus the same ESLint/Prettier
presets as above.

## Consuming in a **React PWA**

**1. Import the CSS variables** in your root stylesheet:

```css
/* src/index.css */
@import "@jrm/tokens/css";
@tailwind base;
@tailwind components;
@tailwind utilities;
```

**2. Apply the Tailwind preset:**

```js
// tailwind.config.cjs
module.exports = {
  presets: [require("@jrm/tailwind-preset")],
  content: ["./index.html", "./src/**/*.{ts,tsx}"],
};
```

Now theme-aware utilities are available: `bg-background`, `text-foreground`, `bg-primary`,
`text-accent-ink`, `rounded-md`, `shadow-lift`, `text-player-3`, `animate-pop-in`, …

**3. Set / toggle the mode:**

```tsx
function setTheme(mode: "light" | "dark" | "high-contrast") {
  if (mode === "light") delete document.documentElement.dataset.theme;
  else document.documentElement.dataset.theme = mode;
}
```

**4. Typed tokens** for anything CSS can't reach:

```tsx
import { tokens } from "@jrm/tokens";
<Sparkline stroke={tokens.color.success} />;
```

**5. Shared configs:** `"extends": "@jrm/tsconfig/react.json"` + the ESLint/Prettier presets.

## Adding a product theme

Copy `packages/tokens/tokens/themes/default/` to `…/themes/<your-theme>/`, restyle the
four color files (keep the semantic names — that's the contract), and register a Style
Dictionary instance in `packages/tokens/config/style-dictionary.config.mjs`. Every primitive
scale, semantic typography/motion token, and component binding is reused unchanged.

## Constraints

- **No publishing** — `pnpm install` / `pnpm build` / `pnpm -r build` for local verify only;
  packages stay `private` + `0.0.0` until publishing is wired.
- **Tokens are framework-agnostic** — the CSS-vars output works in plain CSS, Svelte, and
  React alike.
- Conventional-commit style; no secrets.
