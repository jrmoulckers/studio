# Agent Instructions - JRM Studio

This file is the portable repository entry point. Generic personas and capabilities come
from the canonical agent definitions; Studio-specific constraints and handoffs come from
this repository.

## Precedence

1. Mandatory platform and safety rules.
2. The nearest Studio instruction file and every applicable realm principle.
3. The canonical agent's generic role guidance.

Local Studio rules win when generic guidance conflicts with a product constraint. Before
working, read the authoritative local dispatch map in
[`principles/AGENTS.md`](principles/AGENTS.md), then every realm file for the work. Cite
the principle behind a decision; propose a principle when the tree is silent.

## Critical Studio constraints

- Studio is a pnpm + Turbo design/tooling kernel, not a product app. Preserve the
  `@jrm/tokens` -> `@jrm/tailwind-preset` dependency direction and keep config packages
  independent of product repositories.
- Tokens follow primitive -> semantic -> component references and ship framework-neutral
  CSS variables to Next.js, Svelte/Vite, React/Vite, and Gradle/KMP consumers.
- `packages/tokens/build/` is disposable build output; `packages/tokens/dist/` is the
  committed, byte-for-byte sync interface. Never hand-edit either.
- Every package remains private and `0.0.0`. Record consumer-impacting changes with a
  changeset, but do not publish.
- Local-first products keep durable user-owned data on-device first, place optional sync
  behind a provider seam, and boot without secrets.
- Shared packages carry no personal data. Analytics must never contain finance content or
  join identity across products.

Provider-specific agent files are not local extension points. Future
`.github/agents/*.agent.md` files must be generated by the canonical sync; do not create
or edit them by hand.
